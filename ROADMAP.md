# ROADMAP — План разработки FlyGotchi

Документ описывает пошаговый план развития проекта **FlyGotchi** от текущего каркаса (FastAPI + WebSocket-заглушка 20 Hz, PixiJS v8 арена, Docker Compose для Linux и Windows/WSL2) до полноценного релиза цифрового питомца на базе коннектома *Drosophila melanogaster* (FlyWire / FAFB).

Задачи оформлены в виде единого общего бэклога. Для каждой задачи указаны конкретные действия и ожидаемый результат.

---

## Текущая отправная точка (v0.1.0 — каркас)

- **Backend (`backend/src/main.py`):** FastAPI-приложение с `/health`, WebSocket `/ws/brain`, фоновой заглушкой `ConnectomeSimulator` (20 тиков/сек), обработкой команд `feed`, `poke`, `stimulate_vision` и работой с путями через `pathlib.Path`.
- **Frontend (`frontend/src/`):** React + TypeScript + Tailwind CSS + PixiJS v8 (`FlyArena.tsx` с отрисовкой схематичной мухи, интерполяцией координат и кликом-стимулом, `TelemetryPanel.tsx`, `useBrainSocket.ts`).
- **Инфраструктура:** `docker-compose.yml` с hot-reload (polling для WSL2), `.gitattributes` (`eol=lf`), `.gitignore`, каталог `data/.gitkeep`.

## Этап 1. R&D и подготовка данных (Мозг и коннектом)

Цель этапа — получить воспроизводимый локальный датасет коннектома FlyWire и формализовать соответствие между биологическими нейронами и игровыми входами/выходами.

- [ ] **1.1. Изучение архитектуры вычислительной модели (*Shiu et al. 2024* и аналоги)**
  - **Что сделать:** Разобрать референсную модель спайковой сети мозга дрозофилы (*Drosophila* Leaky Integrate-and-Fire на графе FlyWire, ~139k нейронов, ~50M+ синапсов / сжатая разреженная матрица). Зафиксировать уравнения мембранного потенциала $V_i(t)$, синаптических токов (экспоненциальный спад), рефрактерного периода $\tau_{\text{ref}}$, порога спайка $V_{\text{th}}$ и знаков весов (возбуждающие / тормозные по нейромедиаторам: ACh, GABA, Glut). Оценить время одного шага на CPU (NumPy/SciPy sparse vs PyTorch sparse vs Brian2).
  - **Ожидаемый результат:** Короткая архитектурная спецификация (например, в `docs/brain_model.md`) с выбранным фреймворком расчёта (рекомендуется `scipy.sparse` / `torch.sparse_csr` для минимального оверхеда на CPU), параметрами шага интегрирования ($\Delta t = 0.1\text{–}1.0\text{ мс}$) и целевым бюджетом вычислений.

- [ ] **1.2. Поиск, верификация и подготовка матриц весов и таблиц классификации**
  - **Что сделать:** Найти и скачать открытые артефакты FlyWire / *Shiu et al. 2024* (таблица нейронов с `root_id`, типом нейромедиатора, суперклассом/классом, координатами в пространстве FAFB/JRC2018F и списком направленных связей с количеством синапсов `syn_count`). Проверить лицензию данных и совместимость форматов (`.csv` / `.parquet` / `.npz`).
  - **Ожидаемый результат:** Зафиксированы URL/источники датасета, контрольные суммы (SHA256) и схема колонок; проверена возможность упаковки графа в разреженную матрицу весов (`scipy.sparse.csr_matrix` в `.npz`) для быстрой загрузки при старте бэкенда.

- [ ] **1.3. Кроссплатформенный скрипт загрузки и подготовки `download_brain.py`**
  - **Что сделать:** Написать скрипт `backend/scripts/download_brain.py` (строго через `pathlib.Path`, без привязки к `/` или `\`, с поддержкой `FLYGOTCHI_DATA_DIR`), который скачивает сырые таблицы, проверяет хэши, строит нормализованную разреженную матрицу связей (`connectivity.npz`) и индекс нейронов (`neurons.parquet` / `neurons_index.json`) в каталог `data/`. Добавить поддержку кэширования (пропуск скачивания, если артефакты уже валидны) и пробросить команду запуска в `README.md`.
  - **Ожидаемый результат:** Запуск `python backend/scripts/download_brain.py` (на Linux, Windows/WSL2 или внутри контейнера) автоматически наполняет `data/` готовыми к симуляции файлами, не попадающими в Git.

- [ ] **1.4. Карта соответствий нейронов (Sensory & Motor Mapping)**
  - **Что сделать:** На основе аннотаций FlyWire составить конфигурацию `data/neuron_mapping.json` (или генерируемую скриптом таблицу) с группами `root_id` для:
    - **Входы (Sensory):** зрительные нейроны (Lamina/Medulla/Lobula, LC-нейроны детекции движения/приближения), вкусовые рецепторы сахара (GRNs: Gr5a/Gr64f — сладкое), обонятельные рецепторы (ORNs), механорецепторы (щетинки/антенны, реакция на прикосновение/поток воздуха).
    - **Выходы (Motor / Descending Neurons):** нисходящие нейроны (DNs) ходьбы вперёд/поворота (например, группы P9/DNa02), чистки лапок/усиков (grooming, aDN), вытягивания хоботка (PER — Proboscis Extension Reflex, MN9), аварийного взлёта/прыжка (Giant Fiber / GF).
    - **Кластеры телеметрии:** агрегированные пулы для `vision`, `motor`, `mushroom_body`, `hunger`, `central_complex`.
  - **Ожидаемый результат:** JSON/Parquet-маппинг, связывающий реальные `root_id` коннектома с понятными программными каналами входа и выхода без хардкода в основном коде симулятора.

## Этап 2. Реализация ядра симуляции (Backend Engine)

Цель этапа — заменить заглушку `ConnectomeSimulator` на реальную спайковую модель мозга с сохранением стабильного WebSocket-потока.

- [ ] **2.1. Модуль спайковой нейросети (LIF Engine)**
  - **Что сделать:** Вынести симулятор из `backend/src/main.py` в отдельный пакет `backend/src/brain/` (например, `lif_network.py`, `loader.py`, `simulator.py`). Реализовать векторизованный шаг LIF-модели на базе загруженной матрицы весов из `data/`: обновление потенциалов $V$, генерация спайков $S = (V \ge V_{\text{th}})$, сброс потенциалов, рефрактерный таймер, вычисление постсинаптических токов $I_{\text{syn}} = W \cdot S$ (с учётом знака нейромедиатора) и фонового стохастического шума.
  - **Ожидаемый результат:** Работающий класс `SpikingBrain`, способный просчитывать $N$ шагов симуляции в секунду на CPU и возвращать массив спайков / частот разрядов по индексам нейронов.

- [ ] **2.2. Переводчик «Событие в мире -> Сенсорный импульс» (Sensory Encoder)**
  - **Что сделать:** Реализовать модуль `sensory_encoder.py`, который преобразует события среды и команды клиента в инъекцию тока / пуассоновские спайковые поезда в соответствующие входные группы из `neuron_mapping.json`:
    - Приближение курсора / клик (`poke`) -> всплеск в механорецепторах и LC-зрительных нейронах пропорционально близости к мухе и углу зрения.
    - Источник света -> тоническая стимуляция зрительных долей.
    - Капля сахара / `feed` -> активация вкусовых GRN-нейронов сладкого и последующее снижение метаболического голода.
  - **Ожидаемый результат:** Внешние воздействия вызывают каскады спайков, распространяющиеся от сенсорных входов вглубь коннектома.

- [ ] **2.3. Переводчик «Моторные спайки -> Поведение мухи» (Motor Decoder)**
  - **Что сделать:** Реализовать `motor_decoder.py` с фильтрацией спайковых частот (скользящее окно / экспоненциальное сглаживание по выходным DNs) в параметры кинематики и дискретные поведенческие состояния:
    - Асимметрия левых/правых DNa02 -> угловая скорость поворота;
    - Суммарная активность локомоторных DNs -> скорость ходьбы;
    - Пик в Giant Fiber -> быстрый отскок/взлёт (`startled` / `flying`);
    - Активность PER / grooming нейронов -> состояния `feeding` / `grooming`.
    - Добавить физику границ арены и обратную связь (столкновение со стенкой стимулирует антеннальные механорецепторы).
  - **Ожидаемый результат:** Движение и поведение мухи на арене управляются не скриптами, а реальной активностью выходных нейронов коннектома.

- [ ] **2.4. Нейромодуляторы и циркадный ритм**
  - **Что сделать:** Добавить в симулятор внутреннее гомеостатическое состояние:
    - **Октопамин** (стресс/возбуждение от частых `poke` или угрозы) -> повышает общую возбудимость и порог перехода к полёту;
    - **Дофамин** (награда при поедании сахара) -> усиливает сигнал вознаграждения (PAM-нейроны грибовидных тел);
    - **Серотонин** и **циркадный таймер** (внутриигровые сутки или реальное время) -> переводят муху в состояние покоя и сна при снижении стимуляции.
  - **Ожидаемый результат:** Поведение мухи меняется во времени в зависимости от усталости, сытости, стресса и времени суток.

- [ ] **2.5. Оптимизация тикрейта и WebSocket-протокола**
  - **Что сделать:** Разделить внутренний физический шаг нейросети (например, $\Delta t = 0.5\text{–}1\text{ мс}$, пачками по 10–50 подшагов за один тик) и частоту отправки телеметрии клиенту (20–30 Hz). Внедрить компактный формат кадров: передавать агрегированные активности кластеров, состояние мухи и (опционально по подписке для режима «Рентген») сжатый список активных узлов/зон вместо полного дампа 139k нейронов. Добавить поддержку бинарных фреймов или дельта-обновлений при необходимости.
  - **Ожидаемый результат:** Стабильный поток по `/ws/brain` без перегрузки сети и просадок FPS на клиенте (размер базового пакета < 1–2 КБ).
